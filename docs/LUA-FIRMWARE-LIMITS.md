# Lua 转换与鼠标固件执行边界

本文区分“解析 Lua”“运行软件 Lua”“把等价动作写成固件宏”。本项目当前核对的是 HID++ `0x8100` 描述中的 **宏格式 1**；配置格式 7、10 与宏格式不是同一字段。写入配置和宏数据不等于安装 Lua 解释器，也不构成固件升级。

## 已有固件原语

以下依据 [libratbag 的宏格式定义](https://github.com/libratbag/libratbag/blob/master/src/hidpp20.h)及本项目已经核对的字节码；这些是原语集合，不是对每个鼠标固件的实测承诺。

| 字节码 | 表达的操作 | 对转换的意义 |
| --- | --- | --- |
| `00` | 等待一个宏步长的空操作 | 步长未建立精确定时语义，不能当成任意计算或零毫秒 Sleep |
| `01` | 等待绑定此宏的实体键松开 | 可表达按下片段 → 松开片段，不能指定另一个键 |
| `02` | 绑定键仍按住时从宏入口重复 | 可表达整个动作段的按住循环，不能指定循环起点或查询任意按键 |
| `03` | 持续重复直至取消 | 取消途径依固件验证，不能仅凭这个名称保证“再次按同一键关闭” |
| `40` | 16 位毫秒延迟 | 静态延迟可编码；更长有限延迟需要分段，并检查实际释放行为 |
| `41`–`46` | 鼠标、键盘、媒体键的按下/松开 | 可表达已确定的输入动作；需正确映射键码并配对持有状态 |
| `20`、`21`、`61` | 纵横滚动、相对位移 | 可表达相应数值动作，不等于绝对坐标或屏幕反馈 |
| `60` | 无条件跳转到页/偏移 | 用于宏存储的连接；没有变量操作数、条件码或返回栈 |
| `FF` | 结束 | 单个程序结束与存储分配边界 |

已公开的这组指令中，没有任意变量、读取其他鼠标键、读取键盘状态、条件分支、文件、网络或运行 Lua 字节码的指令。不能用“生成几个动作”声称保留了这些运行时语义，也不能把某次试跑得到的动作轨迹当作所有输入序列的转换结果。

## 可以证明的降级形式

| Lua 行为 | 转换条件 |
| --- | --- |
| 常量、局部计算、有限数值循环、有限函数调用 | 值在编译时可确定，展开有界且最终动作序列相同 |
| 选定鼠标键的按下事件 | 静态选择该事件分支，并把动作绑定到明确的目标实体键 |
| 同一键的按下及松开事件 | 按下段 + `01` + 松开段；需验证事件编号、跨段持有和快速松开 |
| 整段 `while IsMouseButtonPressed(选定键)` | 循环体可以静态确定；仅需要从入口重复时可用 `02` |
| 独立按下一次 + 按住循环 + 松开一次 | 不能简单写成“按下 + 循环体 + `02` + 松开”；`02` 重复入口且其后的动作未被证明会执行 |
| 独立开关键修改全局变量，左右键根据变量工作 | 单个动作宏没有对应的跨事件变量/条件原语；软件层或额外的有限状态路由方案才能表达 |
| 随机数、锁定键、修饰键、其他鼠标键、时钟决定分支 | 不能在导入时取一次值后固定；这种采样会改变后续行为 |

特别是 `03` 的取消语义存在资料边界：[libratbag 未合并 PR #1895](https://github.com/libratbag/libratbag/pull/1895) 的工具说明明确警告无限循环可能没有已验证的取消方式；它还说明 `02` 之后的动作不会按预期作为释放段执行。[Solaar 的按键编码](https://github.com/pwr-Solaar/Solaar/blob/master/lib/logitech_receiver/hidpp20.py) 则定义了单独的“停止宏”和“停止所有宏”绑定行为。编码定义的存在，不足以证明目标固件能取消特定循环，也不能把软件层的 Toggle 状态机结果用作硬件证明。

2026-10-31 用户的 G502 HERO 诊断记录已确认：旧版确实写入了末尾 `03 FF` 的左键循环，第二次实体按键不能按预期关闭。当前 `MacroCompiler.Compile(..., Toggle)`、`MacroProgram.ToOnboard()` 与宏分配入口均拒绝该错误转换；不会把 Toggle 降级为 WhileHeld。软件执行与 Lua 导出仍保留 Toggle 状态机。恢复旧数据时，仅把这类字节识别为旧的持续循环，不将“停止宏”绑定错误恢复成“执行宏”。这不等于已经修复鼠标固件的同键开关能力。

## 开关侧键 + 左右键执行：可研究的板载路由

对“一个布尔开关、固定的左右键动作、其余设置相同”这一受限需求，可以使用两个板载配置承载状态；这是额外的配置路由方案，**本说明不表示当前已经实现或实机验证**。

| 当前状态配置 | 左右键 | 同一开关侧键 |
| --- | --- | --- |
| OFF | 原有普通动作 | 下一配置（功能 `08`），进入 ON |
| ON | 对应的固件宏 | 上一配置（功能 `09`），返回 OFF |

该方案的前提和约束：

1. 选择两个相邻、可写、启用的配置槽；没有足够槽位时拒绝，不能覆盖用户其他配置。两份配置应从同一基线克隆并完整展示差异。
2. 不用“循环所有配置”（功能 `0A`）冒充布尔开关；存在其他启用槽时，它会经过其他配置。特定配置选择功能 `0D` 的编号基准也须在目标设备核对后才能使用。
3. 模式、DPI、回报率、灯效、其他按键保持一致；保留至少一个普通左键映射及可达的关闭入口。不能偷偷重映射其他按键作为应急入口。
4. 两份配置、所有宏、目录必须合成一个以原始快照为基线的事务：宏先写，配置随后，目录最后；提交前全量备份，逐扇区读回，失败按原始字节完整恢复。不能直接连续调用两次独立写入来伪称原子事务。
5. 这只表示一个有限状态机，不是通用 Lua VM。配置切换时对正在执行的宏如何取消、是否释放所持按键，以及开关与左右键同时按住时的行为，必须在目标固件单独验证。
6. Lua 软件事件按顺序执行时，侧键事件可能排在一个尚未结束的按住回调后；硬件配置切换可能立即发生。因此不能不加条件地宣称它与任意 Lua 脚本的全部事件交错完全等价。

另一种受限路由是硬件 G-Shift 层：按住 G-Shift 键时让左右键执行另一层动作。但这是“按住修饰键”语义，不等于“按一下锁定，再按一下关闭”，也不能静默替换脚本中的布尔开关。

## 三种编号必须分开

- G HUB Lua 参数：`1` 左键、`2` 中键、`3` 右键、`4/5` 后退/前进。
- 固件鼠标动作位：第 1 位左键、第 2 位右键、第 3 位中键。
- 板载按键记录与 G 编号：按具体型号布局决定。例如本机已核对的 G502 X PLUS 前进键是记录 `5` / G6，不能直接用 Lua 的 `arg - 1` 得到记录 `4` / G5。

导入选中的 Lua 事件和最后绑定的实体键应分别显示。用户主动改绑属于配置选择，不能把这种变化描述为原脚本触发条件完全未变。

键盘还另有数字扫描码命名空间。官方 G HUB Lua API 的 `PressKey(30)` 对应 A，数字 `2` 对应主键区的 1，不能把它们当作 ASCII 或 USB HID usage。当前静态转换表以本机官方 `G_series_Lua_API.pdf` 附录 A（43–45 页）核对，仅接受已列扫描码，并明确支持其中的扩展编码，例如 `0x11D` 右 Ctrl、`0x11C` 数字小键盘 Enter；未知、分数和非有限数值应拒绝。软件 Lua 与板载转换共用同一张表，避免数值和键名产生不同输出。

## 验证和报告要求

转换器应给出可转换的动作段、触发事件、实际目标键、每一个延迟、所需配置槽、宏格式和空间占用。不能等价表示的分支应返回具体位置与原因，保留原脚本，继续允许在已实现 API 范围内的软件 Lua 层执行。

差分测试应比较原 Lua 与生成程序在按下、松开、快速点击、长按、第二次触发、按键交错等事件轨迹下的输出与状态；覆盖中/右键编号及按下/松开配对。测试可以证明所建模原语下的编译一致性，不能替代鼠标固件的执行测试。写入后字节一致也不能证明宏已被硬件执行，更不能证明断电保持、取消语义或所有新增型号的行为。

2026-10-29 研究记录：本说明未执行固件更新、板载写入或实体按键测试。现有 G502 X PLUS 的已验证宏与延迟不因本文研究而改变。
