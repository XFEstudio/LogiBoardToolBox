# Lua 导入、软件执行与板载转换

通过“按键分配 → 宏 → LUA 脚本”导入 `.lua`，支持 UTF-8（含 BOM）和 UTF-16 LE/BE BOM。最大文件 16 MiB；导入、软件运行、转换和导出统一支持最多 4,194,304 个 UTF-16 字符。导入不执行源码，损坏编码、过大文件和不支持的扩展名会显示具体错误并保留原脚本。

大源码在编辑器内分段显示，每段约 32,768 字符；“上一段 / 下一段”只改变显示，保存、导出、执行和转换都使用完整源码。编辑当前段后操作其他功能会先提交当前段。转换在后台运行，支持取消；取消不会生成部分宏。静态表上限 65,536 项，确定性计算预算 2,000,000 步。长宏时间线分段加载，完整动作和录制延迟仍保留。

源码大小与鼠标板载容量是两种限制。转换器在有目标配置和按键时预估宏区占用，实际绑定时再次检查。分配器复用已有宏页的空隙，并回收不再被其他配置/层引用的替换宏空间；不会覆盖共享宏。如果仍超出设备存储，会列出所需指令字节、可分配字节和宏区总容量，保留源码及原配置，可减少动作或使用软件执行。

对一轮动作固定的 `while true do … end` 和 `repeat … until false`，默认转换为“持续循环”。板载只存一轮动作与固件循环指令，循环次数不占用额外空间。按下启动后，松开按键或关闭软件仍会继续。可以在“按键分配 → 操作”中把“停止所有宏”分配给另一个鼠标键。“按住时重复”在松开时停止，同键启停的“触发”需要鼠标固件声明对应能力。

## 导出

Lua 编辑页的“导出 .lua”将当前源码原样保存为 UTF-8 文件；“保存脚本”仍用于保存本地脚本库，两者相互独立。取消系统保存对话框不会修改源码。

普通宏也可以从“板载与执行 → 导出为 .lua”生成 Lua。先选“Lua 导出触发事件”，再导出；选项采用左 1、中 2、右 3、后退 4、前进 5 的 Lua 编号。生成文件保留动作、延迟和播放方式，不改变鼠标当前绑定。遇到 G HUB Lua 没有对应 API 的指令，会明确拒绝导出，不丢弃指令。

生成脚本包含用于准确回读的版本及校验信息。重新导入时需同时通过校验和完整脚本文本核对；修改过的代码会重新走普通 Lua 转换流程，不会被旧的元数据覆盖。保存使用同目录临时文件及原子替换；导出失败或取消写入不会破坏已有目标文件。

导出的循环宏使用 1ms 物理键状态轮询实现取消。持续循环的停止键写在 Lua 文件开头，默认用鼠标按钮 5，触发键为 5 时用 4。短于轮询间隔的脉冲不能保证捕获，真实 G HUB 的事件积压行为仍需对应环境验证。导出/回读的指令一致性与该物理事件时序验证分别记录。

## 软件执行

勾选左键或右键执行后明确启用。鼠标编号遵循 G HUB：1 左、2 中、3 右、4/5 侧键；软件内部自动转换为 Windows 的按钮编号。触发只监听物理事件，忽略脚本注入的输入，防止脚本自身再次触发。原始点击正常透传。关闭脚本会取消启动、长 Sleep 和正在执行的循环，并释放按键；保存只保存源码与左右键选项，程序重启后不会自动开启。

支持的 API：`OnEvent`（PROFILE_ACTIVATED、MOUSE_BUTTON_PRESSED、MOUSE_BUTTON_RELEASED）、`Sleep`、`EnablePrimaryMouseButtonEvents`、`IsMouseButtonPressed`、`IsKeyLockOn`、`IsModifierPressed`、`GetRunningTime`、`OutputLogMessage`、`PressKey` / `ReleaseKey` / `PressAndReleaseKey`、对应鼠标按钮 API、`MoveMouseRelative`、`MoveMouseWheel`。键盘支持名称和官方 Lua API 扫描码：数字 `30` / `0x1E` 表示 A，数字 `2` 表示主键区 1，字符串 `"1"` 也表示数字键 1；不会把数字扫描码误当作 HID Usage。未实现的 G HUB API 和未定义扫描码不会被静默模拟。

示例：按住左键时连续点击，保留 59/198 ms 两段延迟：

```lua
EnablePrimaryMouseButtonEvents(true)
function OnEvent(event, arg)
    if event == "MOUSE_BUTTON_PRESSED" and arg == 1 then
        repeat
            PressMouseButton(1)
            Sleep(59)
            ReleaseMouseButton(1)
            Sleep(198)
        until not IsMouseButtonPressed(1)
    end
end
```

实现采用 [MoonSharp 的模块限制](https://www.moonsharp.org/sandbox.html)和[可抢占协程](https://www.moonsharp.org/coroutines.html)，没有文件、系统命令、网络或 CLR 导入模块。事件队列、源码、执行时间和无让出的指令执行均有边界。完整 G HUB Lua API、任意第三方扩展和操作系统库不在支持范围内。

## 板载转换

选择左、右、中键或侧键事件，再点“检查并生成板载宏”。单次、按住时重复、持续循环和可等价表达的序列可由板载执行。“触发”需要设备声明同键启停能力，未声明此能力的设备可用软件执行。转换器通过静态解析提取确定性动作。

| Lua 内容 | 转换方式 |
| --- | --- |
| 数组、嵌套配置表、字段和索引 | 根据确定值展开；保留表引用与局部作用域规则 |
| 数值 for、ipairs、确定顺序的数组 pairs | 按真实迭代次序展开，受转换计算预算及目标设备存储容量约束 |
| 有限 while / repeat、break、return、do 块 | 按确定条件展开 |
| 一轮动作固定的 while true / repeat until false | 将一轮动作与无条件重复指令写入板载 |
| 局部函数、参数、返回值与闭包常量 | 在对应词法作用域求值；不能把跨事件可变状态当常量 |
| math.floor / ceil / abs / min / max 等确定性运算 | 预计算数值；不采样随机数或当前系统状态 |
| 选定按键的按住循环 | 保留可表达的固件重复模式 |
| MOUSE_BUTTON_PRESSED + RELEASED | 保留独立点击/松开片段，自动使用序列和等待松开屏障 |
| 仅 RELEASED 有动作 | 先等待实体键松开，再执行动作 |
| 重复按下/松开与已按住键上的击键 | 按 Lua 输入状态去重，避免误释放原先按住的键 |

生成宏不会用标准延迟覆盖原始 Sleep。侧键事件编号不等于 G4/G5/G6 的绑定记录编号；无法从当前配置确认目标实体键时，需在普通宏编辑器中明确选择。

例如上述脚本可生成左键按住循环。需要同键启停时，使用普通宏编辑器的软件“触发”模式或保留原 Lua 在软件层运行。可转换的板载程序会打开普通宏编辑器，保存并选择实际目标按键绑定。选中板载配置时由既有自动保存事务完成备份、写入和读回；未知格式或不兼容能力仍会阻止写入。

依赖 NumLock/CapsLock、动态条件、跨事件开关状态、未知 API、不能确定的循环等无法在现有固件指令中保持语义，会明确拒绝转换并保留源码。它们可以在受支持的软件 API 范围内继续执行。转换不等于把 Lua 解释器烧录到鼠标；能否脱离软件执行，取决于设备的真实板载能力。

固件没有通用条件跳转、跨事件变量或随机数指令，不能把这些能力通过截图或取一次主机状态伪装成板载支持。独立的“按下一次 + 按住循环 + 松开一次”若不能由现有指令精确表达，也会保留为软件执行。相关原生指令与边界见 [固件转换范围](LUA-FIRMWARE-LIMITS.md)。

当前软件 Lua 引擎在负除数 `%` 上存在与 Lua 标准不一致的边界行为，因此转换器会明确拒绝此情况，不复制该错误。可将 `a % b` 改为标准表达式 `a - math.floor(a / b) * b`。正除数（包括负被除数）的取模正常转换。
