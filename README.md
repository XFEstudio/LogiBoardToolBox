# LogiBoardToolBox

沿用 .NET 10、WinUI 3、CommunityToolkit.Mvvm 与 XFEExtension 架构的罗技鼠标配置工具。型号身份与原图目录现覆盖本机 G HUB 可核对的 **43 款鼠标**，包括 G502 各代、GPW3 / SUPERLIGHT 2、GPW4 朱雀 / PRO 2。图片随程序分发，不依赖目标电脑安装 G HUB。目录覆盖不代表全部型号的板载功能已实测；板载布局与可用功能以连接设备实际返回的能力为准，实机写入与宏输出目前在 **G502 X PLUS / 046D:C547** 上验证。完整目录见 [型号与原图](docs/MODEL-ARTWORK.md)，原有功能验证范围见 [多型号支持](docs/MULTI-DEVICE-SUPPORT.md)。

设备界面依据用户截图和本机 G HUB 页面、资源与交互逻辑重做，新增板载自动读写。**基础板载宏已通过物理按键实测；目前仍未达到 G HUB 全功能、全界面完全一致，断电保持尚未实测。**

## 使用

Lua 入口位于“按键分配 → 宏 → LUA 脚本”。导入或粘贴源码，选择左右键执行选项后点“启用脚本”；点“关闭脚本”立即取消并释放按键。保存的脚本不会随程序自动启动。要离开软件运行，使用“检查并生成板载宏”，选择提取的左/右键事件及板载播放方式，再在普通宏编辑器中绑定实体键。只会转换明确支持的指令；完整限制和示例见 [Lua 使用说明](docs/LUA-SUPPORT.md)。

打开设备后自动扫描并读取。多只鼠标可在设备设置中的“设备诊断与软件配置”选择；切换前完成旧设备自动保存，再读取新设备。右上角选择“桌面: 默认”编辑软件配置，选择实际提供的“板载配置”后直接编辑相应板载槽。DPI X/Y、闲置秒数、配置名称和颜色文本在输入时仅保留草稿，按 Enter 或离开输入框后才校验并提交；Esc 撤销草稿。无效数值保留上次有效设置，不进入保存队列。已确认的有效修改在约 200ms 内合并后自动保存，无需再点写入；事务串行执行，每次自动备份、检查旧数据并逐扇区读回。正在执行的闪存事务不会被后续手势取消。失败会显示错误并保留编辑内容；仍有保存失败时不会直接关闭窗口。

宏库、软件配置、自定义灵敏度预设和自动备份位于 `%LOCALAPPDATA%\LogiBoardToolBox\Onboard`。项目、程序集及可执行文件统一更名为 `LogiBoardToolBox`；首次使用更名版本时会复制旧 `LogiBordToolBox\Onboard` 数据目录，保留原目录且不覆盖已有新宏库，即使配置框架已提前创建新产品目录也能迁移。旧版本生成的板载备份仍可读取和恢复。软件宏需从宏编辑器的“板载与执行”启动；LIGHTSYNC 页面用户进入时可接管软件灯效，停止或关闭会恢复控制。

完整独立按住循环序列、自由灯区及动画的 EEPROM 播放布局尚未验证；这些功能不会被静默转换成其他板载效果。屏幕、音频联动仍需要电脑。HERO 成功校准、触发循环及其他高级宏的物理执行、应用自动切换、G HUB 集成/社区仍有未完成或未确认项，不能视为 G HUB 全功能替代。

此次故障定位在 Windows 接收器键盘读取路径：恢复前，匹配微软驱动符号的 HIDCLASS 跟踪显示，17 字节键盘报告已经到达集合 1，但完成读取 IRP 数为 0，键盘集合持续 `NumPendingReads=0`；同接口的媒体集合正常完成读取。重新连接使设备重新枚举，随后原生键盘输出恢复。最初导致读取循环停止的触发原因仍未确定，没有证据认定某个其他程序导致故障。`work/ghub-binding-fix/driver-read-path-summary.json` 保留恢复前的历史跟踪，`keyboard-output-failure-summary.json` 汇总当前恢复结果与历史对照。

此前已经修复的协议与存储差异继续保留：板载切换/保存及软件会话最后退出前关闭 `0x8110/2` 按键监听；Shift 使用 G HUB 原生 `43 02 E1` / `44 02 E1`；宏分配遵循终止符后的两字节对齐。取消刀位于扇区 8 偏移 0，左键连点位于同扇区偏移 26，G5/G6 绑定顺序正确。单独应用这些修正时，用户仍反馈取消刀无效，因此没有把这些修正当作此次恢复的直接原因。原始宏扇区保留，所有临时对照均已恢复。历史证据在 `native-reference-audit.json`、`aligned-entry-repair`、`receiver-keyboard-path` 等目录中。

`--audit-receiver <目录>` 只读导出设备功能表、固件和接收器寄存器，不设置通知标志、不配对、不切模式、不生成输入；本机读到接收器 4.2.9，检查前后扇区、模式和活动槽一致。

`--reload-onboard-runtime <目录>` 是仅针对上述已核对设备的一次性恢复命令：先备份，最多等待 60 秒，连续输入空闲至少 5 秒且鼠标常规按键均松开才允许重载；输入恢复或配置变化则跳过。它仅短暂重建主机/板载运行状态，强制返回原板载槽，核对闪存和性能，不调用宏执行函数、不写入闪存。不得把运行状态恢复成功当作宏执行成功。

`--replug-keyboard-comparison <目录>` 是需用户明确配合的 90 秒拔插对照：释放 HID++ 句柄后，仅观察目标接收器 Raw Input、设备到达/移除及透传的数字 1 校准，结束后重新读取配置验证一致性。命令不会写入、触发宏、切换前台或拦截输入。

管理员诊断工具 `Receiver-RepairHost.ps1` 使用进程和本地任务队列；曾验证同一进程内的请求复用和子任务错误隔离，但该进程在 2026-10-24 恢复工作前已经退出，未实现跨轮持续可用，不能把启动元数据当作当前存活证据。此次恢复没有再次申请 UAC。此前单个键盘子设备重启返回 Windows 3010（需要重启系统），没有执行系统重启；键盘/媒体 USB 接口恢复脚本始终仅做预检，未执行接口重启。
